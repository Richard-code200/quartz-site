Linux 的环境变量设计有一点挺有趣，它有一个简单易懂的安全设计。

一般情况下，执行 `ls` 这样的外部命令，不用刻意敲出它的具体路径，shell 会自动到环境变量 `PATH` 指定的目录里寻找对应的程序。

但在编程过程中，需要运行自己编译出来的程序时，一般会这样写：

```sh
./程序名
```

这里的 `.` 表示当前目录。`./程序名` 的意思就是运行当前目录下对应名字的可执行文件，而不是去 `PATH` 里找。这样可以避免编译产物和环境中的工具重名，导致运行错了程序。

另一方面，平时执行命令时不默认搜索当前目录，也能避免误运行同名的恶意程序。

比如在不知情的情况下下载了一个包含恶意程序的项目，里面有一个恶意可执行文件也叫 `ls`。

如果 shell 优先搜索当前目录，而不是 `PATH` 中的目录，那么在这个项目里执行 `ls`，就可能运行到那个恶意程序。

所以这里的关键是：**当前目录通常不在 `PATH` 中**。需要运行当前目录下的程序时，就用 `./程序名` 这样的路径明确指定。

当然，如果自己把 `.` 加进了 `PATH`，尤其放在前面，就会重新引入这个风险。主动执行 `./ls` 也还是会运行当前目录下的文件，并不是加了 `./` 就安全了。

Windows 的 PowerShell 和 macOS 的常见 shell 也有类似的设计。只不过 PowerShell 下通常写成 `.\程序名.exe`，具体还要看 `PATH` 的配置。
